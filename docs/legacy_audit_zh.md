## 為什麼 2D 能畫圖

附件 2D 的第 127–133 行先取 0–1 的 x、y、t，再分別除以 0.2 m、0.1 m、60 s。網路看到的空間範圍是 0–5 與 0–10，訓練時間只覆蓋物理上的 0–1 s。第 524–543 行卻把評估延伸至 60 s。其第 169–170 行直接把瓦數除以通量尺度，亦缺少實際接觸面積。

GitHub 的兩個 2D 版本在第 130–134 行改成先取真實範圍的 x、y、t。它們將兩熱源都除以最大功率，產生 0.6 與 1 的相對目標。若將 30/50 W 同比例提高為 60/100 W，目標完全不變。它們又將平面內的 y 梯度套在內部熱源區，無法表示由下蓋沿 z 方向輸入的熱量。GitHub 的 2D 版本亦已對部分高 Péclet 方程縮放，所以 2D 與 3D 的 loss 數值不能直接比較。

附件 `PINN_test_20241013.py` 第 542–555、665–686 行是整機風扇轉速、表面溫度與噪音迴歸，沒有 x、y、z、t 場或兩相均溫板方程。第 477–523 行從同款機種衍生樣本，之後第 612–613 行逐列隨機拆分，驗證資料可能包含同款機種的變體。第 624–632、739–746 行把標準化後的量直接代進按物理量寫的經驗式，分母也可能接近零。這條支線宜以按機型留出和物理單位的約束另外驗證。

## 核對異常溫度與兩相解釋

附件 3D 第 101–108、505–511 行明確使用 T[°C] = 30 + 40θ，θ = 0 就是 30 °C。要從這段程式輸出 −273 °C，需要 θ 約 −7.58。原始檔沒有從 θ 直接減 273.15，缺少該次 checkpoint、逐項 loss 與原始 θ，無法把使用者見到的溫度精確歸因於單一轉換錯誤。應先核對初始場、插值時域、每一個熱源及冷凝面所通過的瓦數，再對照同時同地的感測器資料。

舊模型以單一液態水的 k 與熱容解能量方程，沒有蒸氣壓力、相變潛熱、汽液交換、毛細壓差或可識別的配方依賴。壓力僅透過梯度進入方程，缺少參考值。熱源表面、液體、均溫板外殼與晶片接面有不同溫度，測點標示應連同厚度、感測器深度、接觸熱阻及環境條件一起保留。

三份提供的簡報分別交代 PINN 示範、工作流體構想與材料篩選假說。其內容可用來訂試驗項目，未提供這十個配方在這個幾何下可校正的原始溫度時間序列、重複試驗與分區熱流資料。配方順位、75–85 °C 晶片溫度與 50–70 °C 工質溫度均應由匹配工況的量測檢驗。

## 用小批點直接呼叫舊的訓練步驟

以 TensorFlow 2.20 CPU 與 Keras 的種子 42 載入附件 3D，保留原始網路、PDE、邊界採樣與 optimizer，取原順序前 32 個內點及 8 個初始點。首次編譯執行 `train_step` 所回傳的更新前 loss 為 7.3025 × 10¹¹，其 PDE 部分約 7.3025 × 10¹¹、邊界部分約 0.0696、初始條件部分約 0.728。這次計算的二階自動微分與單步更新順利執行。這是量級與程式路徑的重現，完整 20,000 步與使用者的特定 checkpoint 沒有在此測試中重跑。
